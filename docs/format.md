# Notes folder format

The storage contract shared by the macOS and Windows apps. The folder on disk is the only source of truth; there is no database, index or app-specific metadata.

## Layout

- **Root**: a folder chosen by the user (macOS default: `~/Documents/Notes`, Windows default: `%USERPROFILE%\Documents\Notes`). Created if missing. An app may show several roots side by side (a workspace, like VS Code); each root follows this contract on its own, paths are relative to their root, and roots may not be nested inside one another. The list of roots is app preference, not stored in the folders.
- **Notes**: every regular file whose extension is `md` (case-insensitive) is a note. The note's display name is the file name without the extension. Only notes are created by New Note and named automatically.
- **Encrypted notes**: regular files whose extension is `mdenc` (case-insensitive) are password-protected Markdown notes (see *Encrypted notes*). Their display name is the file name without the extension. They are listed, opened in the Markdown editor once unlocked and shown with the Markdown-only filter, but they are not notes in the sense of the rules below: New Note does not create them and they are never named automatically. An app that does not implement *Encrypted notes* does not list them (they are ignored like unlisted files).
- **Other text files**: regular files with one of these extensions (case-insensitive) are listed, searched and editable too, but are not notes: `json`, `swift`, `js` `mjs` `cjs` `jsx` `ts` `tsx` `mts` `cts`, `py`, `sh` `bash` `zsh`, `yaml` `yml`, `xml` `html` `htm` `plist` `svg`, `css`, `c` `h` `cc` `cpp` `hpp` `m` `mm` `java` `kt` `kts` `cs` `go` `rs`, `sql`, `toml` `ini`, `markdown` `mdown` `mkd`, `txt`, `log`, `csv`. They are shown with their full file name (extension included). Markdown files with the longer extensions open in the Markdown editor, the rest in a code editor with syntax highlighting; JSON can be reformatted ("Format"). They are never renamed automatically.
- **Large files**: files over 20 MB open read-only; files over 200 MB are not opened. Sizes are checked again when a file is reloaded after an external change: past 200 MB the last text read stays on screen, read-only. Styling is skipped for texts over 2,000,000 UTF-16 code units.
- **Read-only files**: a file the user may not write (permissions, locked item, a folder that refuses writes) opens read-only with a notice instead of failing every save. A symbolic link whose target is missing is not opened or written.
- **Folders**: every subdirectory is a folder, nested to any depth. Empty folders are kept and shown.
- **Ignored**: any file or folder whose name starts with `.` or that the OS marks hidden (macOS hidden flag, Windows Hidden attribute, e.g. `desktop.ini`), and everything below it (e.g. `.git/`), and every file without one of the extensions above (including files without an extension). Apps never list, modify or delete ignored entries.
- **No sidecar files**: apps write nothing but the files and folders themselves (and conflict copies, see *External changes*). Pinning, ordering, tags, timestamps etc. are not stored; modification time comes from the file system.

## Paths and names

- An item is identified by its path relative to the root, using `/` as the separator on every platform (e.g. `Work/Plans/2026.md`). Paths are split at the Unicode scalar U+002F, never at grapheme clusters (a `/` followed by a combining mark is still a separator).
- **Existing items** (anything found on disk) are opened, renamed and trashed whatever their names, so files made by other programs (`Why?.md`, `10:30.md`) keep working. A path is only rejected when a component is empty or starts with `.` (which covers `.`, `..` and hidden names), so it can never leave the root. On Windows a component containing `\ : * ? " < > |` or ending in `.` or a space is rejected too, and entries whose name ends in `.` or a space are not listed: Windows cannot create such names, and Win32 would resolve them to another item (`bar.`, `bar ` → `bar`), a stream or a wildcard.
- **Names the user types** (new folder, rename) and automatic names must follow the portable rules. A name must:
  - be non-empty,
  - not start with `.` (checked on the first Unicode scalar),
  - not end with `.` or a space (checked on the last Unicode scalar),
  - not contain `/ \ : * ? " < > |` or control characters (U+0000–U+001F, U+007F–U+009F), checked per Unicode scalar,
  - not be a Windows reserved device name: `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, compared case-insensitively on the part before the first `.` with trailing spaces ignored (`con.md`, `Nul.txt` and `LPT1 .md` are reserved; `CONSOLE`, `COM10`, `x.CON` are not).

  These are the Windows file name rules, enforced on both platforms so a folder stays portable. Leading/trailing whitespace is trimmed from user-entered names. A typed name that breaks them is rejected with an error.
- Creating a note appends `.md` if the name lacks it. Renaming keeps the parent folder (a rename never moves an item to another folder). A note keeps its `.md` extension. Another file keeps its extension unless the new name ends in one of the listed extensions: `config.json` → `ayarlar` gives `ayarlar.json`, `ayarlar.yaml` changes it, and `Toplantı 3.5` gives `Toplantı 3.5.json` (`5` is not a listed extension).
- Two names the file system treats as the same file (case-insensitive volumes, Unicode case folding) are the same item; renaming an item to such a spelling of its own name is allowed and goes through a temporary name. If the second step fails, the item is moved back to its old name.

## Automatic naming

Notes are named after their first line, like Apple Notes. Nothing is stored to remember this; it is derived from the name and the content. Only notes (`.md`) inside a root are named automatically, and only while the app's automatic naming setting is on; other text files and Markdown files opened from elsewhere keep their names.

Definitions used below:

- A **line** runs up to (not including) LF (U+000A); a CR (U+000D) right before the LF is ignored. A lone CR, U+2028 etc. are not line breaks.
- **Whitespace** is the Unicode `White_Space` property. A line is **blank** when it has only whitespace.
- Steps work on **Unicode scalars**; "characters" in the length cap are **grapheme clusters** (extended).
- A **number suffix** is a space followed by ASCII digits without a leading zero, with value ≥ 2 (` 2`, ` 12`; not ` 1`, ` 02`, ` 2a`).

Rules:

- **Localized names**: the names apps write follow the app's UI language (the language the app itself is shown in, not the system's preferred-language list; a language the app has no translation for falls back to English): the untitled name is `Untitled` in English and `Adsız` in Turkish; the conflict marker is `conflict` in English and `çakışma` in Turkish. Reading never depends on the language: both untitled names are recognized everywhere.
- **New note**: created at once, without asking for a name, as `<untitled>.md` (`Untitled.md` / `Adsız.md`); if the file system already has an item by that name in the folder (in its own case/Unicode folding), `<untitled> 2.md`, `<untitled> 3.md`, … New folders still ask for a name.
- **Title** of a note's content:
  1. Take the first line that is not blank (leading blank lines are skipped; only as much of the note as needed is read). If it is a thematic break (`---`, `***`) or a code fence, there is no title.
  2. Remove Markdown syntax: heading `#`s (and a closing `#` run), `>` quote markers, list markers (`-`, `*`, `+`, `1.`, `1)`), task boxes (`[ ]`, `[x]`), matched emphasis/strikethrough/code delimiters, link and image syntax (`[text](url)` and `![text](src)` → `text`) and the backslash of backslash escapes. Then trim leftover `*`, `_`, `~`, `` ` `` and whitespace from both ends. Everything else stays text and goes through step 3, for example:
     - autolinks and bare URLs: `<https://a.com>` → `https---a.com`, `https://ex.com/yol` → `https---ex.com-yol`;
     - inline HTML and comments: `Merhaba <b>dünya</b>` → `Merhaba -b-dünya--b-`;
     - entities are not decoded: `Tom &amp; Jerry` → `Tom &amp; Jerry`;
     - escapes: `a\_b` → `a_b`, `\# değil` → `# değil`, `a\\b` → `a-b`; a trailing backslash is kept: `Satır sonu \` → `Satır sonu -`;
     - link reference definitions and tables are plain text: `[x]: https://a` → `[x]- https---a`, `| a | b |` → `- a - b -`.
  3. Make it a valid name, per Unicode scalar: drop `?` and `*`; `"` becomes `'`; `\ / : < > |` become `-`; control characters and whitespace become spaces, and runs of them collapse to one space (none at the start). Then drop leading grapheme clusters whose first scalar is `.` or a space. Then normalize to Unicode NFC.
  4. Cap the length: if it has more than 60 grapheme clusters, take the first 61; if the last space among them has at least 30 clusters before it, cut there, otherwise keep the first 60. Then remove clusters from the end while it is over 200 UTF-8 bytes. Then strip trailing `.` and spaces.
  5. If nothing is left, or only `-` and spaces, there is no title.
  6. If the result is a reserved device name (see *Paths and names*), insert `_` after the part before the first `.` with its trailing spaces: `CON` → `CON_`, `nul.txt` → `nul_.txt`.
- **Auto-named**: a note is auto-named when its name (without `.md`), or that name without a number suffix, is one of the untitled names (`Untitled`, `Adsız`) or equals the title of its content. Names compare after NFC normalization, case-sensitively (`alışveriş` is not `Alışveriş`). This is decided when the note is opened, reloaded after an external change, or renamed by the user (renaming its folder does not count), and holds in between. Any other note was named by hand and is never renamed automatically.
- **Sync**: after each save of an auto-named note, if its first line (not the first non-blank one) is not blank and has a title that differs from both the current name and the name without its number suffix, the file is renamed to that title, made unique in its folder with ` 2`, ` 3`, … (a name is taken when the file system already has an item by that name other than the note's own file, so a case-only change is allowed). If the first line is blank or yields no title, the name is kept. If the rename fails, the note keeps its name and the rename is tried again after the next save.

## Drafts (app state, outside the notes folders)

A new tab opens a draft: an unsaved note that lives only in the app until the user saves it. Drafts are app state, not part of any notes folder.

- Store: one UTF-8 file per draft, named `<32 lowercase hex>.md`, in the app's own folder (Windows: `%LOCALAPPDATA%\Notes\Drafts\`, macOS: `~/Library/Application Support/Notes/Drafts/`), plus `order.txt` listing the draft file names in tab order. Written atomically like notes. Apps never put drafts or anything else into a notes folder before the user saves.
- One app process owns the store at a time, holding an exclusive lock on `.lock` in it (released by the OS when the process ends; macOS uses `flock`). A process that can't get it keeps its drafts in a pending store of its own (Windows: `%LOCALAPPDATA%\Notes\PendingDrafts\<guid>\`, macOS: `~/Library/Application Support/Notes/PendingDrafts/<uuid>/`, locked the same way), says so once, asks before closing a window with non-empty drafts, and on exit moves them into the real store if the lock has become free. Moved drafts get new draft names and are appended to `order.txt`. A pending store that could not be moved stays on disk, and the next process that owns the real store adopts every pending store whose lock it can take, the same way, before restoring. Restore ignores `.lock`, `order.txt` and any name that isn't a draft name.
- A draft whose file changed on disk since it was last read or written here (another writer) is not overwritten: the local text goes to a new draft file and the tab follows it; the old file stays and is restored last.
- Drafts survive closing the app, quitting and logging off without a prompt, and come back as tabs in their order. Empty draft files are deleted at startup. Closing a non-empty draft tab asks Save / Don't Save / Cancel.
- Saving a draft writes `<title>.md` (the title as in *Automatic naming*, else the untitled name, made unique) into the folder selected in the sidebar, else the first root, then deletes the draft file; from then on it is an ordinary auto-named note. Saving an empty draft does nothing. Save As writes anywhere the user picks.

## File contents

- Encoding: **UTF-8**. Apps write UTF-8 **without a BOM**; on read a leading BOM is tolerated and ignored.
- Line endings: apps write **LF** (`\n`). On read, CRLF (`\r\n`) is tolerated and treated as a line break; a file is converted to LF the next time it is saved. A lone CR is ordinary text and is kept. Text entering an editor (typed, pasted) is converted the same way (a leading BOM dropped, CRLF to LF), so the text an app holds always equals what it writes and reads back, and a save is never mistaken for an outside change.
- Files are written atomically: write to a temporary file on the same volume, then replace the original in a way that keeps its metadata (`ReplaceFile` on Windows). On macOS permissions, Finder tags, most extended attributes and the hidden flag are kept; the resource fork (`com.apple.ResourceFork`), the quarantine attribute and hard links are not (the file gets a new inode). Where the private temporary folder can't be used (some network shares), the temporary file is a hidden `.<uuid>.tmp` next to the original. Symbolic links are followed: the link stays and its target is replaced; a link to a missing file is never written.
- Markdown flavour: **CommonMark** plus the GitHub Flavored Markdown extensions **strikethrough** (`~~text~~`) and **task list items** (`- [ ]` / `- [x]`). Other syntax is kept verbatim as plain text.

## Encrypted notes

An encrypted note is one file in the notes folder, `<name>.mdenc`, holding a Markdown note encrypted with a password. Nothing else is stored anywhere: no key file, no password hint, no list of encrypted notes. The file name is not secret (it is shown locked); the content is.

**File layout** (binary; integers big-endian; offsets in bytes):

| Offset | Size | Field |
| --- | --- | --- |
| 0 | 8 | magic: ASCII `NOTESENC` |
| 8 | 1 | format version: `1` |
| 9 | 1 | key derivation: `1` = PBKDF2-HMAC-SHA256 |
| 10 | 4 | iterations (UInt32) |
| 14 | 16 | salt |
| 30 | 12 | nonce |
| 42 | n | ciphertext (n ≥ 0) |
| 42 + n | 16 | authentication tag |

- **Cipher**: AES-256-GCM. The key is PBKDF2-HMAC-SHA256 of the password (normalized to Unicode NFC, then UTF-8) with the salt and iteration count from the header, 32 bytes. The additional authenticated data is the whole 42-byte header, so a change to any header byte fails authentication too.
- **Plaintext**: the note's text in the on-disk form of *File contents* (UTF-8 without a BOM, LF line breaks); it may be empty. Text that is not valid UTF-8 after decryption is reported as a damaged file.
- **Writing**: apps write version `1`, key derivation `1`, 600,000 iterations and a random 16-byte salt when a file is first encrypted or its password changes. Every save of the same file with the same password keeps the salt and iterations (so the key is derived once per unlock) and uses a new random 12-byte nonce; a nonce is never reused with a key. Files are written atomically as in *File contents*; the temporary file holds only ciphertext.
- **Reading**: a file shorter than 58 bytes or without the magic is not an encrypted note ("damaged"). An unknown version or key derivation is reported as made by a newer app, and the file is left alone. Iteration counts outside 10,000–10,000,000 are rejected as damaged (no unbounded work for a hostile file). A wrong password and tampered or damaged data can not be told apart: both are reported as "The password is wrong or the file is damaged."
- **Size limits** of *Large files* apply to the file size.
- **Test vector** (for checking an implementation byte for byte): password `correct horse`, salt bytes `00 01 … 0f`, 10,000 iterations, nonce bytes `00 01 … 0b`, plaintext `# Merhaba\nşifreli not\n` (UTF-8) give the file `4e4f544553454e43010100002710000102030405060708090a0b0c0d0e0f000102030405060708090a0b59043478fa207924476c2c15bf69de34aaf25bac4a610f213beff55d3b7b60643ffafff21e5309` (hex).

**Unlocking** (app behaviour):

- A locked note shows its name and a password field instead of its text. Passwords entered while the app runs are kept in memory only, never written to disk or the Keychain; opening another encrypted note tries the passwords already entered (newest first) before asking. Keys are derived off the UI thread.
- **Locking** forgets every password and key, saves pending edits of unlocked encrypted notes (encrypted), then drops their text and undo history from memory; their tabs show the locked state. The app locks on File > Lock Encrypted Notes, when the screen locks or the Mac goes to sleep, after a set time without keyboard or mouse input (app setting: 1, 5, 10, 30 or 60 minutes or never; default 10 minutes), and on quit. A save that fails while locking keeps the note unlocked and reports the failure, so no edit is dropped. A lock always wins: a key derivation that was running when the app locked is discarded, and a command waiting in a dialog stops when it finds its note locked. A locked tab that becomes active, and every locked open note after a password is typed, tries the passwords already entered.

**Encrypting and decrypting** (app behaviour):

- **New Encrypted Note** (File menu; folder and root menus in the main window's sidebar) asks for a name (the portable rules of *Paths and names*) and, if no password was entered yet, a new password typed twice; it creates `<name>.mdenc` (made unique like a new note) with empty text where New Note would put a note (the folder whose menu was used, else the main window's selected folder) and opens it unlocked.
- **Encrypt…** on a saved `.md` note (File menu, sidebar file menu; not for drafts or other text files) asks for the name (prefilled with the current one) and the password (the last one entered, or a new one typed twice). Unsaved edits are saved first. It writes `<name>.mdenc` (unique in the folder), reads it back and decrypts it to check it equals the note's text, and only then removes the `.md` file permanently, not to the Trash, which would keep the plaintext; this is the one exception to *Deleting*. A note that is a symbolic link or has more than one hard link is not encrypted (removing the name would leave the plaintext under the other one). Before the first encryption in a run the app says that copies kept elsewhere (Time Machine, sync history, git) are not removed. If any step before the removal fails, the `.mdenc` file is deleted again and the note is left as it was.
- **Renaming** never adds or removes `.mdenc`: an encrypted note keeps it whatever the new name ends in, and for any other file a typed `.mdenc` ending is part of the name (`todo.txt` renamed to `todo.mdenc` gives `todo.mdenc.txt`). Save As of an unencrypted file to a name ending in `.mdenc` is refused. Only Encrypt and Remove Encryption convert.
- **Remove Encryption…** on an unlocked encrypted note first checks that the `.mdenc` file still holds the bytes last read or written here (otherwise it stops; the reload brings the newer version), then writes `<name>.md` (unique in the folder) with its text, reads it back to check it, then moves the `.mdenc` file to the Trash. The note is hand-named afterwards (it keeps its name).
- Open tabs, pins and recents follow both conversions like a rename.

**What never sees the plaintext**: the sidebar shows no preview for encrypted notes (date only); search matches their names, never their content; drafts are never encrypted and encrypted notes never become drafts; conflict copies of an encrypted note are encrypted with the same key (`<name> (conflict).mdenc`); pasting or dropping images into an encrypted note is refused with a neutral message (the file in `assets` would be plain), images it already links to are shown; session state, pins and recents hold only paths, selections and scroll positions, and a restored encrypted note opens locked. The plaintext is held in memory only, as long as the note is unlocked (best effort: memory is not wiped).

**Duplicate, move and copy in** treat an encrypted note as bytes: the copy has the same password. **Save As** of an unlocked encrypted note writes an encrypted copy with the same password (the name always ends in `.mdenc`). Commands that need the text (export, print, Save As, Remove Encryption, Format) are unavailable while the note is locked, and a locked note is never saved. **External changes**: an encrypted note that changed on disk is decrypted with its key on reload; if that fails (password changed elsewhere), the note locks and asks again. The conflict check of *External changes* applies, comparing the file's bytes with the bytes last read or written here where it would compare texts (an unchanged stamp, under the same size and timestamp conditions); when the stamp changed, the disk file is decrypted and its text compared.

**Exporting**: see *HTML export*. Exporting or printing an encrypted note as HTML or an unprotected PDF asks first, because it makes an unencrypted copy.

## Display order

Within a folder: subfolders first, then files (notes and other text files together, by display name); each group in localized natural order (case-insensitive, numbers compared by value: `2` before `10`), as by Finder / Explorer (`localizedStandardCompare` on macOS, `StrCmpLogicalW` on Windows).

Apps may offer two display preferences, which change nothing on disk: sorting by last modified (folders still first and by name, then files newest first, ties by name) and showing only Markdown files (`md`, `markdown`, `mdown`, `mkd`; folders are always shown), which hides the other files from the tree and from search.

## Links

Links in Markdown files are followed from the editor with a plain click or a ⌘-click (Ctrl-click on Windows); a click that only places the caret or ends a drag-selection does nothing. Arrow keys still move through link text, so it stays editable.

- **Web addresses**: any destination with a scheme (`https:`, `http:`, `mailto:`, `file:`…): a letter, then letters, digits, `+`, `-` or `.`, at least 2 characters before the `:`, also bare URLs and `<autolinks>`, opens in the system's default app. A single letter before `:` (`C:\x.md`) is a path, not a scheme. `file:` URLs follow the rule for local files below.
- **File links** `[text](path)`: a relative path, percent-decoded, without `#fragment` and `?query`, resolved against the folder of the note that holds the link, with `.` and `..` resolved. The target must be inside the same root: `..` above the root resolves to nothing, and the disk is not tried for it either (neutral "not found" message). Matching ignores case and Unicode normalization; a path without extension also tries `.md`. A target that is not among the listed files, or a note outside the roots, is looked up on disk relative to the note's folder; a listed text file opens in a tab, any other file in its default app. Absolute paths (`/…`) are looked up on disk. **A click never runs a program**: when the target (also of a `file:` URL) is an application or bundle, an executable (macOS: executable bit; Windows: `.exe`, `.com`, `.bat`, `.cmd`, `.ps1`, `.vbs`, `.msi`, `.lnk`, `.scr`), or a script or installer (`.command`, `.sh`, `.app`, `.pkg`, `.scpt`, `.workflow`…), it is shown (selected) in Finder / File Explorer instead of opened.
- **Wiki links** `[[Note name]]`, `[[Note name|shown text]]` and `[[Note name#heading]]`: only the part before `|` and `#`, trimmed, names the target. The name is compared with every listed file of every root: its display name (file name without `.md`), its full file name (`config.json`), or its path without `.md` (`Work/Plan`, matching from any folder boundary). Comparison folds case with NFC + lowercase, plus Turkish `ı` and `İ` to `i`, so `ÇALIŞMA` finds `çalışma`. Several matches: same folder as the linking note, then same root, then `.md` notes before other files, then fewer path components, then path order, then the order of the roots.
- A target that does not exist is reported with a neutral message ("There is no note named …"); nothing is created. An opened target goes to a tab: an already open tab is focused, otherwise a new tab opens next to the current one.
- `[[…]]` is styled like a link (brackets as dimmed markers, name as link text). Inside code spans and fenced code it is plain text. Brackets inside the name, or an empty name, make it plain text.

## Editing helpers (Markdown editor)

Each is one undo step. Ranges are UTF-16 offsets; text in the editor has LF line breaks.

- **Return in a list or quote** continues it with the same indentation: `-`, `*`, `+` keep their character, numbered items count up (`9.` → `10.`, `)` kept), task items continue as `- [ ] `, quotes repeat their `>` markers (`> - a` continues as `> - `). The text after the caret moves to the new item. Return on an empty item (marker only, or marker and box) removes the marker and indentation (inside a quote only the quote prefix stays), ending the list. Nothing is continued when a selection exists, the caret is before the text of the item, a marker has no space after it (`-`, `2025.`), the line is a thematic break (`---`, `- - -`), or the line is inside a fenced code block. Following numbers are not renumbered.
- **Tab / Shift-Tab** on a list item line, or on a selection whose lines are all list items, adds or removes one level at the start of the line's indentation (after any quote prefix): 2 spaces for bullets and tasks, the width of the marker plus its space for numbered items (`1. ` = 3, `10. ` = 4). Shift-Tab removes one tab or up to one level of spaces. Anywhere else Tab inserts a tab as before.
- **⌘K (Ctrl+K)** turns the selection into `[selection](|)` with the caret in the parentheses; an empty selection gives `[|]()`; a selected `http(s)` address becomes `[|](address)`.
- **Formatting actions** (formatting bar, Format menu, shortcuts; each is one undo step and works on UTF-16 ranges). On macOS the formatting bar's controls sit in the window toolbar. The bar can be turned off (View > Show Formatting Bar, default on); it is disabled for read-only files. Windows uses Ctrl where macOS uses ⌘ and Alt where macOS uses ⌥ (⌃ on macOS has no Windows counterpart; Ctrl+Alt+C is suggested for inline code).
  - **Inline styles** toggle a marker pair: **Bold** `**` (⌘B / Ctrl+B), **Italic** `*` (⌘I / Ctrl+I), **Strikethrough** `~~` (⇧⌘X / Ctrl+Shift+X), **Inline code** `` ` `` (⌃⌘C / Ctrl+Alt+C). An empty selection acts on the word (letters, digits and combining marks) at the caret, keeping the caret's place in it; away from a word it inserts the pair with the caret between, and a caret between an empty pair removes it. Surrounding whitespace of a selection stays outside the markers, and each line of a multi-line selection is wrapped on its own. If the markers are already there, outside the selection or as its first and last characters, they are removed instead; bold and italic combine (`***x***`, and removing one leaves the other). The selection afterwards covers the text without the markers.
  - **Line styles** apply to every line the selection touches (a selection ending right after a line break leaves out the next line; blank lines are skipped unless nothing else is selected; nothing happens inside fenced code): **Bulleted list** `- ` (⇧⌘8 / Ctrl+Shift+8), **Numbered list** `1. ` counting 1..n over the changed lines (⇧⌘7 / Ctrl+Shift+7), **Checklist** `- [ ] ` (⇧⌘L / Ctrl+Shift+L), **Quote** `> ` (⇧⌘' / Ctrl+Shift+'), **Heading 1-3** `#`..`###` (⌥⌘1-3 / Ctrl+Alt+1-3) and **Body** (⌥⌘0 / Ctrl+Alt+0, removes the heading marker). If every line already has the style it is removed (quote: one `>` level); otherwise it replaces any other list or heading marker (the existing bullet character and indentation are kept; a heading drops indentation and list markers; quote prefixes stay). Line breaks (CRLF) of the lines are kept. The caret keeps its place in the text of its line.
  - **Code block** (⌥⌘K / Ctrl+Alt+K) wraps the selected lines (the caret's line when nothing is selected, an empty block on an empty line) in ``` fences, using a longer fence when the text contains backticks; a selection that is exactly a fenced block (first and last line are fences) is unwrapped instead. **Horizontal rule** (⇧⌘H / Ctrl+Shift+H) puts `---` on its own line after the selection's last line, with a blank line before it (a blank caret line is used itself), and moves the caret to the line after; it does nothing in fenced code.
  - The bar highlights the styles at the caret (bold, italic, strikethrough, code from the markers around the word or selection; heading level, list, checklist, quote from the line).
- **Markdown syntax** (app setting "Markdown syntax": dimmed or hidden; macOS toggles it with View > Show Markdown Syntax, ⇧⌘M): hidden markers (`#`, emphasis and code delimiters, link brackets and destinations, escapes, code fences; never quote `>`s, list markers, task boxes or table pipes) take no room and stay real text. The ones the selection touches show (either end counts: a heading's `#`s when the caret is right after them, a fence when the caret is on its line), and so do both delimiters of an emphasis, code span or link whose text or delimiters the selection touches. **Reading mode** (macOS: View > Reading Mode, ⇧⌘E, also in the toolbar; app setting, remembered) makes every open file non-editable and hides the markers everywhere, the selection included; Show Source still shows the plain text.
- **Code backgrounds and current line** (editor drawing, no effect on the text): in the Markdown view each fenced code block (``` or ~~~, fence lines included, an unclosed fence runs to the end) gets one full-width band in the theme's `codeBlockBackground` behind all its lines, drawn under the text and the selection; inline code keeps a background behind its glyphs only (`inlineCodeBackground`). Bands are not drawn in Show Source mode or when the text is too long to style (2,000,000 UTF-16 units). With the setting "Highlight current line" (default on) and an empty selection, both editors draw the theme's `currentLine` band behind every wrapped fragment of the caret's line (not the room under an inline image); a non-empty selection shows only the selection colour. The code editor also draws the caret line's number in the normal secondary colour while the other line numbers are dimmed (alpha 0.5). Only the old and the new line rectangles are redrawn on a selection change.
- **Tables** (GFM pipe tables: a header line with a pipe, a delimiter row with the same number of cells (`---`, `:--`, `:-:`, `--:`), then following lines with a pipe up to the first blank line). A pipe is a cell separator unless it is escaped (`\|`) or inside a code span. A leading and trailing pipe are optional; four spaces of indentation or more, and anything in fenced code, is not a table.
  - **Insert Table** (⇧⌘T / Ctrl+Shift+T; a picker of up to 8 × 8, rows including the header) inserts an empty aligned table after the selection's last line like the horizontal rule does (blank line before and after) with the caret in the first header cell. **Convert Selection to Table** turns the selected lines into a table, the first line being the header: tab-separated if any line has a tab, otherwise comma-separated (double quotes allowed, `""` is a quote); `|` in a cell is escaped; short rows are padded; needs at least two columns, otherwise nothing happens.
  - **Tab / Shift-Tab** in a table moves to the next / previous cell and selects its text (the delimiter row is skipped); Tab in the last cell adds a row; Shift-Tab in the first cell is the normal Tab. **Return** in a row adds an empty row below it (below the header for the header row) with the caret in its first cell; Return in an empty last body row removes it and leaves the table with the caret on the new line below (a blank line is kept between the table and following text). Each of these re-aligns the whole table (one undo step; nothing but the caret moves if it is already aligned): every row is `| cell | cell |` with cells padded with spaces to the widest cell of the column (at least 3), alignment respected (right: padded left; center: padded both sides, extra space on the right), delimiter row `---`, `:--`, `:-:`, `--:` filling the width. Widths count extended grapheme clusters, 2 for East Asian wide characters and emoji (including ZWJ and VS16 sequences), 1 otherwise. Rows with more cells than the header widen the table instead of losing text; indentation of the table is dropped; line breaks (CRLF) are kept.
  - **Format > Table**: Add Row Above / Below (above is not available on the header; below the header or delimiter row adds the first body row), Add Column Left / Right, Delete Row (body rows only), Delete Column (not the last one), Align Column Left / Center / Right. They act on the cell the caret is in, re-align the table and keep the caret in its cell.
  - The live editor draws pipes and the delimiter row dimmed (they stay visible when markers are hidden) and the header row bold; this is the styler's `tableMarker` and `tableHeader` spans.
- **Clicking a task box** `[ ]` / `[x]` (`[X]` counts as checked) flips it to `[x]` / `[ ]` when the file is editable; the caret does not move. Boxes in fenced code are not task items.

## Images

- **Display**: in the live Markdown editor (not in the source view) `![alt](destination)` shows the image under its line, scaled down to the text width (never up), at most 420 pt tall, aspect kept. The text itself is unchanged; nothing is inserted into it. The destination is a relative path (resolved against the note's folder, percent-decoded, `<…>` form allowed, optional title ignored), an absolute path or a `file:` URL. Remote (`http:`) images are not loaded. A missing or unreadable file shows nothing. Images inside code spans and fenced code are not shown. A file that changes on disk is shown again.
- **Pasting or dropping an image** (image data, or image files from Finder) into a Markdown note that has a file saves it in an `assets` folder next to the note (created if missing) and inserts `![](assets/<name>)` at the caret (one per line for several images), as one undo step. The name is `<note name> <n>.png` with the smallest `n` ≥ 1 that is free (the note name made valid under the portable rules: forbidden characters become `-`, capped at 60 characters, `image` if nothing is left). PNG, JPEG and GIF files keep their bytes and use `.png`, `.jpg`, `.gif`; any other image becomes PNG. The destination is percent-encoded (everything but ASCII letters, digits and `-._~`). The file is written to a hidden temporary file in `assets` and moved into place, so an existing file is never replaced. Undoing the insertion leaves the file in `assets`.
- **Drafts** (notes without a file yet) refuse images with a neutral message ("Save the note first to add images."); nothing is saved. Dropping a file that is not an image behaves as before.
- The `assets` folder is an ordinary folder (listed like any other); its image files are not listed because they have no listed extension.

## Outline

The outline of a Markdown note lists its ATX headings (`#` to `######`, up to 3 spaces of indentation, a space after the `#`s) in document order, with level, text and the UTF-16 offset of the start of the line (the line start, not the first `#`; lines end at LF). The closing `#`s of `## Title ##` and surrounding whitespace are not part of the text; headings without text and lines inside fenced code are left out. Choosing a heading puts the caret at the start of its line and scrolls to it.

## Focus mode

An app setting (not stored in notes). In the Markdown editor every paragraph (text between line breaks) except those the selection touches is dimmed, without changing the text or its styling, and the caret line is kept in the vertical middle of the viewport while typing or moving the caret (not on mouse clicks).

## Moving, duplicating and copying in

None of these ever overwrites an item, and none changes a note's content.

- **Move** (drag and drop in the sidebar): an item goes into another folder or root, or into a root folder itself. Moving it to the folder it is already in does nothing; moving a folder into itself or a descendant is refused. Unsaved edits of the item (or of files inside a folder) are saved first; if that fails the move is cancelled. Open files follow the move. If the destination has an entry by that name (in its own case/Unicode folding), the moved item gets a number: `Plan.md` → `Plan 2.md`, `Plan 3.md`, …; a folder `Plans` → `Plans 2` (the number goes before the extension, folders have none). The name is otherwise kept, even if it breaks the portable name rules (it is an existing item). A move across roots on different volumes copies and then deletes, as the OS does; the macOS app does that in the background (unless a file inside is open) and refuses a second operation on the same item meanwhile.
- **Duplicate** (a file's context menu): a copy next to the file named `<name> copy.<ext>` (`Plan copy.md`; `Plan kopya.md` in Turkish: the marker follows the app's UI language like the untitled name), then `<name> copy 2.<ext>`, `<name> copy 3.<ext>`, …. The name is made portable first (see below). Unsaved edits are saved first. The copy is a hand-named note (it does not follow its first line) and nothing is opened.
- **Copy in** (dropping files or folders from outside the roots, e.g. from Finder): the item is copied into the target folder with a number added as for a move when the name is taken. Only folders and listed files are copied; hidden names (leading `.`) are refused. A folder can not be copied into itself. Unsaved edits of the dropped file (or of files inside the folder) open in any window are saved first; if that fails the copy is cancelled. The macOS app copies in the background.
- **Portable names for copies**: a copied-in or duplicated item is not an existing item, so its name follows the portable rules: each of the stem and the extension has `/`, forbidden characters and control characters replaced by `-`, is normalized to NFC, loses leading `.` and spaces and trailing `.` and spaces (whole Characters), and the whole name is cut to at most 200 UTF-8 bytes at a Character boundary, keeping the extension (before a number is added); a reserved device name gets `_` after its stem; a stem left empty becomes `item`. The same steps (without the extension part, capped at 60 Characters) name pasted images in `assets`.

## Sidebar preview

With the sidebar preview on (app preference, default on), a file row shows its modification date and a one-line preview under the name. The preview exists for Markdown files (never for encrypted notes) and reads only the first 2,048 bytes (a cut inside a UTF-8 sequence is dropped). It is the first non-blank line after the title, that is after the first non-blank line, skipping thematic breaks and fenced code blocks, with the Markdown syntax removed as for titles (heading `#`s, quote and list markers, task boxes, emphasis and code delimiters, link syntax), runs of whitespace collapsed to one space, trimmed of leftover `*`, `_`, `~`, `` ` `` and whitespace, and cut to 200 characters. A file without such a line has no preview.

## Status bar counts

The status bar under the editor shows three counts of the document text (the text in the editor, not the file on disk). **Characters** are user-perceived characters (extended grapheme clusters, so an emoji with a skin tone or a family emoji is one, a precomposed and a decomposed `ş` are one each), not counting line breaks. **Words** are runs of characters that are not whitespace; Markdown syntax is not removed (`# Title` is two words). **Lines** are the line breaks (exactly LF, CRLF, CR, U+2028 and U+2029; VT, FF and NEL are ordinary characters) plus one: empty text and `a` are one line, `a\n` is two, and CRLF counts once. The counts are computed off the UI thread shortly after typing pauses. The bar can be turned off (View > Show Status Bar, default on).

## HTML export

File > Export as HTML… writes a self-contained UTF-8 HTML page (inline CSS, no scripts) of the active file; Export as PDF… and Print… render the same page. A Markdown note is converted: ATX and setext headings, paragraphs (a line ending in two spaces or a backslash is a `<br>`), `*`/`_` emphasis, `**`/`__` strong, `~~` strikethrough, code spans, fenced code blocks (`<pre><code class="language-x">`), bullet and ordered lists (nested; an ordered list starts at its first number; a list with blank lines between items is loose, with `<p>` per item), task items (`- [ ]` / `- [x]`, a disabled checkbox), block quotes (nested blocks), links, images, autolinks and bare `http(s)://` URLs, thematic breaks and pipe tables with alignment. Raw HTML in the source is escaped, never passed through; link and image targets are kept only if scheme-less (relative), `http`, `https` or `mailto`, any other scheme becomes `#`; before the scheme is read, leading and trailing control characters and spaces are dropped and TAB, LF and CR inside are removed, as a browser does. A destination or title that contains an autolink or code span is not a link (left as text). Any other file is one `<pre>` of its text. The CSS uses the neutral greys, the user's text and code font families and base sizes (not the zoom), and a light or dark scheme following the viewer (always light when printing). Relative image paths are left as written in the HTML file, so images resolve only next to the exported file; PDF and Print embed the relative image files of a saved note (image types, up to 25 MB each) so they appear. The suggested file name is the note's name plus `.html`/`.pdf` (dots in the name are kept); the open file itself is never suggested or overwritten.

**Protected exports** (File menu; not while the note is locked): Export as PDF… offers "Protect with password" for any document (a password typed twice); the PDF gets that password as its user and owner password (PDF standard encryption, readable in any PDF viewer; weaker than an `.mdenc` file), and no unprotected PDF is kept on disk (it is rendered into a private folder in the system's temporary folder and deleted right after; only a crash in between can leave it there, where the OS clears it). Export as Encrypted Note… (Markdown documents, drafts included) writes an `.mdenc` copy of the text (see *Encrypted notes*) with the password the user types (twice), with a new salt; the open file is never overwritten. HTML has no password option (it has no scripts).

## Zoom

View > Zoom In / Zoom Out / Actual Size scale the editors' text and code font sizes by one factor from 50% to 300% in steps of 10% (default 100%). It is an app preference and not part of the format; the font sizes chosen in Settings stay as they are.

## Deleting

Deleting a note or folder moves it to the OS trash (macOS Trash / Windows Recycle Bin) so it can be restored. Apps never delete permanently on their own (the one exception is the plaintext original of a note being encrypted, see *Encrypted notes*); where the volume has no trash (e.g. some network shares on Windows), the OS asks the user before deleting permanently, and declining cancels the delete.

## External changes

Other programs (editors, sync clients, git) may change the folder at any time. Apps re-read the tree when they regain focus or when the file system reports a change, and reload an open file that changed on disk unless it has unsaved local edits; the cursor and scroll position are kept.

- **Conflicts**: before saving, an app checks whether the file changed on disk since it was loaded or last saved here: its modification time, size or file identity (inode / file ID) differ from what was recorded after the last load or save. Since some file systems keep modification times to a second or two (HFS+, FAT), the macOS app also compares the disk text with the last saved text when the stamp is unchanged, for files up to 1 MB, and for bigger files only when their modification time is a whole second (a coarse-timestamp volume) and less than two seconds old, so saving a large file on APFS never reads it back. Both texts are compared in their on-disk form (see *File contents*). If it changed and the content differs, the app does not overwrite it: it writes the local text to a new file next to it, `<name> (<conflict>).<ext>` (`(conflict)` / `(çakışma)`, then `(conflict 2)`, `(conflict 3)`, … if taken), opens the disk version and tells the user. If the changed file can't be read (no longer UTF-8, no permission), the local text goes to the conflict copy the same way and editing continues in that copy; the original is left alone. Nothing is lost and no choice is forced in the middle of an autosave or quit.
- **Failed saves** keep the edits in memory and are reported. Switching to another note, renaming or trashing the open note, changing the notes folder, closing its window or quitting does not drop them: the action is cancelled, or the user explicitly chooses to discard the edits.
- **Deleted files**: an open file that disappears is closed only if it is still missing a moment later (some programs save by deleting and recreating) and has no unsaved edits; with unsaved edits the next save recreates it.
- A file opened in two windows is one document: both show the same text.

## Files opened from outside the roots (macOS)

A file that is not inside any root of the main window (opened from Finder, "Open With", the command line) opens in a window of its own, rooted at the file's folder, with the sidebar closed until the user shows it; further files from that folder join that window as tabs. Such a window follows this contract for its folder, with two differences: notes there are never named automatically (the file keeps its name), and ⌘T followed by Save writes the draft into that window's folder (as `<title>.md`, made unique) because it has no selection elsewhere. When a window of this kind is rooted at the home folder or one of its parents, the sidebar lists only a few levels deep. Closing the window moves its drafts, and any file whose last save failed, to the main window; saved files simply close.

## App state (not part of the format)

Besides drafts, apps keep their own state outside the notes folders; none of it is shared or needed to read a folder. The macOS app keeps the list of roots of the main window in its preferences (a root that can't be opened, e.g. an unmounted volume, stays in the list and is shown as unavailable; only the default `~/Documents/Notes` is created when missing, and only on the first run) and the open windows in `~/Library/Application Support/Notes/session.json` (written atomically, only by the process that owns the draft store): per window its outside folder (the main window has none, its roots live in the preferences), the open files by absolute path and drafts by draft file name, the active tab, the source-view toggle, the selection (UTF-16 offsets) and scroll position of each tab, whether the sidebar is shown, and which sidebar folders are open (roots the user collapsed, subfolders the user expanded, by absolute path). Files and folders that are gone are skipped silently on restore.

**Pinned and recent files** are app state too, never stored in a notes folder. The macOS app keeps them next to `session.json` in `pins.json` (pinned files, in pin order) and `recents.json` (the last 10 opened files, newest first), each `{"version": 1, "paths": [absolute paths]}`, written atomically and only by the process that owns the draft store. A pin follows its file when the app renames or moves it (folders included) and is dropped when the app moves it to the Trash; a path that is missing is hidden, not deleted, so a pin on an unmounted volume comes back with it. The pinned files show in a "Pinned" section at the top of the main window's sidebar; the recent files in File > Open Recent. A run without a support folder (a test run) keeps both in memory only.
